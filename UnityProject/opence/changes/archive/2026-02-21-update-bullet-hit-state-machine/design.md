## Context
- 当前代码已有 `IHealth`、`TakeDamage`、`BulletEntity.HandleTriggerEnter2D`、`EntityView` 碰撞桥接。
- 但玩家与敌人的死亡后行为阻断缺乏统一约束：死亡动画播放期间仍可能执行输入、移动或攻击更新。
- 子弹“命中即回收”的语义需要在规格层面固定，避免后续实现出现“命中后仍残留可碰撞对象”的回归。
- 当前子弹数据只有 `OwnerType`，缺少“发射者实体 ID”，无法在角色死亡时精确清理“该角色自己发射”的子弹。

## Goals / Non-Goals
- Goals:
  - 统一子弹命中 -> 目标扣血 -> 子弹回收的最小闭环。
  - 统一玩家/敌人受击后的状态迁移，并约束动画与行为一致性。
  - 支持角色死亡时按发射者精确清理其未命中的在场子弹。
  - 让 Work 阶段能以小范围改动完成交付，不引入新系统。
- Non-Goals:
  - 不引入新的战斗数值系统（暴击、护盾、抗性等）。
  - 不新增复杂动画 BlendTree 或 Animator 参数体系。
  - 不改动技能系统接管攻击的现有扩展点。

## Decisions
### Decision: 继续复用现有伤害入口与动画资源
- `BulletData.Damage` 作为唯一伤害输入。
- 玩家死亡动画继续使用 `Boom`，敌人继续使用 `EnemyDead`。
- 不新增受击动画，仅约束“死亡态切换 + 行为阻断”。

### Decision: 死亡态是行为阻断的唯一真值
- 玩家：以 `_isDead` 作为 `OnUpdate` 里输入与攻击的阻断条件。
- 敌人：在行为状态机中增加/明确 `Dead` 态，进入后停止移动、停留和攻击逻辑。
- 两者均在进入死亡态后禁用碰撞器，防止重复命中。

### Decision: 子弹回收必须显式停用可见对象
- 命中有效目标后调用 `HideEntity` 回收子弹。
- 子弹在隐藏回调中必须保证 `Handle.SetActive(false)`，避免对象池中的可见残留。

### Decision: 采用“发射者 ID + 按需扫描”实现死亡清弹
- 在 `BulletData` 增加发射者实体标识（如 `SourceEntityId`）。
- 在 `IBulletModule` 暴露按发射者清理方法（例如 `ClearBulletsBySource(int sourceEntityId)`）。
- `BulletModule` 在收到清理请求时扫描 `IEntityManager.GetAllLoadedEntities()`，筛选属于该发射者的 `BulletEntity` 并逐个隐藏。
- 选择按需扫描而非常驻索引表，原因是死亡事件低频，优先保持实现简单和低维护成本。

## Risks / Trade-offs
- 死亡动画时长与延迟隐藏秒数若不一致，可能出现动画被截断或空窗停留。
- 子弹命中后立即回收会放弃穿透弹行为；如未来需要穿透，需新增可配置策略而不是修改默认语义。
- 按需扫描是 O(N)；在极端子弹数量下清理瞬时成本会上升，但在当前规模和触发频率下可接受。

## Migration Plan
1. 先补规格（本变更）并通过严格校验。
2. Work 阶段先实现玩家/敌人死亡态阻断，再实现按发射者清弹与子弹隐藏收口，最后做联调验证。
3. 通过场景回归验证“命中扣血、死亡动画、行为停止、子弹回收、死亡清弹”。

## Open Questions
- 无阻塞问题；默认沿用现有动画资源与延迟隐藏策略，并将“角色”解释为玩家与敌人实体。
