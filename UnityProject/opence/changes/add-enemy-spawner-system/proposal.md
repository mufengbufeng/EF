# 添加敌人生成系统

## 动机

当前游戏玩法流程（GamePlayProcedure）已具备场景加载和背景滚动功能，但缺少核心游戏玩法元素——敌人系统。为了让玩家有实际的游戏内容可玩，需要实现：

1. **敌人生成管理**：控制敌人的生成时机、速度和数量，提供可配置的波次生成逻辑。
2. **敌人行为逻辑**：实现敌人的移动、停留和攻击行为，使游戏具备基本的挑战性。

该系统将复用现有的 Entity 模块和 ModuleSystem 的 Scope 管理机制，确保敌人资源在流程切换时能够正确清理。

## 影响范围

### 新增能力
- **enemy-spawner**：敌人生成器模块，负责敌人的波次生成、数量控制和生成速率调节。
- **enemy-behavior**：敌人实体行为系统，定义敌人的移动模式（直线、曲线等）、停留逻辑和攻击触发。

### 修改的组件
- `GamePlayProcedure`：在 OnEnter 中注册敌人生成器模块，在 OnLeave 中通过 Scope 清理。

### 依赖关系
- **依赖 entity-module**：敌人实体通过 `IEntityManager` 创建和管理。
- **依赖 module-scope**：敌人生成器作为 GamePlay Scope 模块，在流程退出时自动清理。
- **依赖 EF.Resource**：加载敌人预制体资源。
- **依赖 EF.ObjectPool**：复用敌人实例，减少频繁创建销毁的开销。

## 技术约束

1. 敌人实体必须继承 `EntityBase` 并实现生命周期回调（OnInit、OnShow、OnHide、OnRecycle）。
2. 敌人生成器必须实现 `IEFManager` 接口，支持 ModuleSystem 统一管理。
3. 敌人行为逻辑通过 `OnUpdate` 每帧驱动，避免使用 Unity MonoBehaviour 的 Update。
4. 敌人生成参数（生成间隔、最大数量、移动速度等）应支持运行时动态调整。
5. 所有敌人模块注册到 GamePlayScope (1001)，确保流程切换时自动清理。

## 风险评估

- **性能风险**：频繁生成大量敌人可能导致性能下降。
  - 缓解措施：使用对象池复用敌人实例，限制同屏最大敌人数量。
- **碰撞检测复杂度**：敌人攻击判定需要与玩家交互。
  - 缓解措施：初期使用简单的距离检测或 Unity Collider，后续可优化为空间分区。
- **配置复杂度**：不同敌人类型可能需要不同的生成参数和行为配置。
  - 缓解措施：使用 ScriptableObject 或配置表管理敌人数据，支持扩展。

## 验收标准

1. 敌人能够按照指定间隔和数量生成到游戏场景中。
2. 敌人能够执行移动逻辑（如从上向下移动）。
3. 敌人能够在到达指定位置后停留一段时间。
4. 敌人能够触发攻击行为（初期可为简单的日志输出或特效播放）。
5. 退出 GamePlayProcedure 时，所有敌人实例被正确清理和回收。
6. 支持运行时调整敌人生成速率和最大数量。
