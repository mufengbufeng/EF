# 添加游戏场景管理器

## 概述

为 EasyFramework 添加基于状态机的游戏场景管理器，支持场景流程管理和异步场景切换。当用户在入口界面点击开始游戏后，系统将自动加载 Game.unity 场景并管理场景的生命周期。

## 目标

- 提供统一的场景流程管理，基于现有的状态机框架
- 支持异步场景加载和卸载，与现有的 ResourceManager 集成
- 提供清晰的场景状态管理，包括加载中、已加载、卸载中等状态
- 与现有的 UI 框架无缝集成，支持在场景切换时显示加载进度
- 确保场景切换的安全性和稳定性

## 动机

当前项目中，EntryController 只有基本的开始游戏逻辑，缺乏完整的场景管理系统。为了提供流畅的游戏体验，需要一个专门的场景管理器来：

1. **统一场景流程**：基于状态机管理场景的加载、运行、卸载等状态
2. **异步加载支持**：利用现有的 ResourceManager 实现异步场景加载
3. **错误处理**：提供完善的错误处理和恢复机制
4. **扩展性**：支持未来添加更多场景和复杂的场景切换逻辑

## 范围

### 包含内容

- 创建 `SceneManager` 核心类，继承自 `AEFManager`
- 基于 FSM 框架实现场景状态管理
- 定义场景状态：空闲、加载中、已加载、卸载中、错误
- 提供异步场景加载和卸载 API
- 与 EntryController 集成，实现开始游戏后的场景切换
- 支持场景切换过程中的进度回调和错误处理

### 不包含内容

- 场景内对象的生命周期管理（由各场景自身负责）
- 复杂的场景预加载机制
- 场景间的数据传递（将在后续版本中支持）

## 受影响的组件

- **EF.Scene**：新增场景管理模块
- **GameLogic.EntryController**：集成场景管理器，实现开始游戏逻辑
- **EF.Resource**：利用现有的场景加载功能
- **EF.Fsm**：利用现有的状态机框架

## 替代方案考虑

1. **直接在 EntryController 中处理场景切换**
   - 优点：简单直接
   - 缺点：耦合度高，难以扩展，不利于复用

2. **使用事件系统进行场景管理**
   - 优点：解耦度高
   - 缺点：缺乏状态管理，难以处理复杂的异步流程

3. **基于状态机的场景管理器**（选择的方案）
   - 优点：状态清晰，便于调试和扩展，与框架风格一致
   - 缺点：初期实现相对复杂

- **中等风险**：与现有系统的集成可能需要调整现有代码
- **低风险**：基于成熟的状态机框架，技术风险较低
- **低风险**：利用现有的 ResourceManager，不涉及底层场景加载逻辑
